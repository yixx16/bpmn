=====================================================================
PRUEBAS CON CURL - G3 Publicar una version del modelo de score (ARCA)
=====================================================================
Los resultados "ESPERADO" salen del diseno del proceso. No se ejecutaron
en un motor Camunda real: verificalos hoy antes de presentar.

Requisitos: Camunda Platform 7.24 corriendo, workers corriendo (node worker.js),
curl y jq. En Windows usa Git Bash (el cmd y PowerShell rompen las comillas del JSON).
Las tareas se completan por REST, asi que NO necesitas grupos ni Tasklist para probar.

---------------------------------------------------------------------
0. PREPARACION (pega esto una vez en la terminal)
---------------------------------------------------------------------
BASE=http://localhost:8080/engine-rest

# Variables de las tareas de usuario
V_CONS='{"fuenteEvidencia":{"value":"DERIVA","type":"String"},"resumenEvidencia":{"value":"El loss ratio se desvio 12% en el ultimo trimestre","type":"String"},"cambioPropuesto":{"value":"Subir el peso de verificacion de fuentes","type":"String"}}'
V_CAL='{"versionCandidata":{"value":"score-v1.3","type":"String"},"datosCalibracion":{"value":"Siniestros 2025-2026","type":"String"},"cambiosSenalesPesos":{"value":"Peso de verificacion de fuentes de 10 a 15","type":"String"}}'
V_DOC='{"referenciaMemoria":{"value":"MC-2026-11","type":"String"},"notaCambios":{"value":"Recalibracion por deriva","type":"String"}}'
V_APRUEBA='{"decisionComite":{"value":"APROBADA","type":"String"}}'
V_AJUSTES='{"decisionComite":{"value":"AJUSTES","type":"String"}}'
V_RECHAZA='{"decisionComite":{"value":"RECHAZADA","type":"String"}}'

# Funciones de ayuda
iniciar() { # $1=businessKey  $2=variables extra en JSON (opcional, ej: ,"simularValidacion":{"value":"falla","type":"String"})
  curl -s -X POST $BASE/message -H "Content-Type: application/json" \
   -d "{\"messageName\":\"NecesidadNuevaVersion\",\"businessKey\":\"$1\",\"processVariables\":{\"motivo\":{\"value\":\"Deriva detectada\",\"type\":\"String\"}$2}}"
  PI=$(curl -s "$BASE/process-instance?processDefinitionKey=Process_G3_PublicarVersionModelo&businessKey=$1" | jq -r '.[0].id')
  echo "Instancia: $PI"
}
completar() { # $1=instancia  $2=variables JSON
  TASK=$(curl -s "$BASE/task?processInstanceId=$1" | jq -r '.[0].id')
  curl -s -X POST "$BASE/task/$TASK/complete" -H "Content-Type: application/json" -d "{\"variables\":$2}"
}
tareas() { curl -s "$BASE/task?processInstanceId=$1" | jq -r '.[].name'; }
estado() { curl -s "$BASE/history/process-instance/$1" | jq '{state, endActivityId}'; }
ruta()   { curl -s "$BASE/history/activity-instance?processInstanceId=$1&sortBy=startTime&sortOrder=asc" | jq -r '.[] | (.activityName // .activityId)'; }

11. SI ALGO FALLA
---------------------------------------------------------------------
- iniciar no crea instancia (PI = null): falta desplegar G3, o el nombre del mensaje no coincide.
- Una tarea de usuario da error de formulario: los .form no viajaron en el mismo despliegue que el BPMN.
- El proceso se queda en una tarea automatica: el worker no esta corriendo.
  Revisa: curl -s $BASE/external-task | jq '.[] | {topicName, workerId}'
- Error al invocar S2: S2.bpmn no esta desplegado (la Call Activity usa la ultima version).
- Si tu Camunda exige usuario y clave en REST, agrega a cada curl:  -u demo:demo
- Para borrar una instancia de prueba:  curl -s -X DELETE "$BASE/process-instance/$PI"
